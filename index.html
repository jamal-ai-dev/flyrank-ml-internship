Abstract

This paper asks which content pages a reviewer should check first when review time is limited. We build a transparent baseline rule from two confirmed signals (CTR falls sharply with search position; decline rate rises with impression volume), train Logistic Regression and Random Forest models on the same client-holdout split, and catch a real feature-label leak before trusting the result. The honest, leakage-free signal reaches Precision@10 = 0.300 against a base rate of 0.248 — real but modest — and is turned into a three-archetype action playbook with explicit no-go rules for what should never be automated.

01

Introduction

A content team with limited review time cannot check every page every month. This paper supports one decision: given a fixed review budget, which pages should be opened first? The unit of analysis is one (client, content) pair, aggregated over a calendar month. The output is a ranked queue; the action a human takes is opening the top rows and deciding whether to refresh, rewrite, or leave a page alone. The cost of a wrong call is real but asymmetric: a false flag wastes a reviewer's morning, a missed decline keeps losing a high-traffic page's visibility unnoticed.

Thousands of pages and one reviewer's time make some form of ranking unavoidable. The real question this paper tests is whether a learned ranking earns its place over a simple, fully transparent rule — and whether that improvement survives honest scrutiny once it's found.

03

Methodology

Label, features, baseline, split design, and the leak we caught before trusting the number.

Label (proxy): a page is flagged is_declining_proxy = 1 when its clicks in the second half of March are lower than in the first half — an observed within-month comparison, not a causal claim.

Baseline: a transparent rule flags pages in the top quartile of first-half impressions whose CTR sits below the median for their position tier. Two signals behind it were confirmed first: CTR falls from 75.0% (position 1–3) to 18.7% (position 21+); decline rate rises from 3.1% to 43.5% across impression quartiles.

Split: grouped by client (client-holdout) — no client's content appears in both train and test, so the model can't learn client-level quirks and get an unfair advantage on "unseen" rows from a client it already saw.

The leak we caught: Logistic Regression and Random Forest both scored suspiciously high (LR: 1.000 Precision@10). Removing the obviously-named suspect feature alone changed nothing — the real cause was a sibling feature (CTR is computed from clicks), both mechanically tied to the label's own zero-click boundary.

The honest model does not beat the baseline rule on this slice — both land at Precision@10 = 0.300. The value of the modeling work here was not a lift over the baseline; it was catching a leak that would have shipped a false 3x improvement had the first, incomplete leak test been trusted.

Errors cluster in one honest, explainable way: pages with genuinely low but stable click-through rates for their query type get flagged as "underperforming" when nothing has actually changed — the model has no way to distinguish "always been this way" from "newly declining" using only the signals available in this window.

05

Limitations & honest framing

Proxy label

is_declining_proxy is an observed within-month click comparison, not a validated causal outcome. A flagged page may have an ordinary explanation (seasonality, a single spike day) this analysis cannot see.

Partial coverage

Only pages with gsc_data_available = true are visible to this analysis — about 36.7% of the raw window. Pages without active tracking are invisible to the queue, not necessarily low-priority.

One month, one lane

Built and validated on March 2026 only. Not yet re-tested on a second month or a different client mix.

Modest, not dramatic

Precision@10 = 0.300 against a base rate of 0.248 is a real, directional, decision-support signal — not a strong discriminator, and not a claim about how any search engine's ranking algorithm works.

Human review, before acting on any flagged page: check for a scheduled or recent title/meta test, a known external cause (seasonality, a spike day, a SERP feature change), and the page's actual business value — a high-impression page is not always a high-value one.

  • Never auto-publish content or title/meta changes from this score alone
  • Never treat "monitor_only" as permanently irrelevant
  • Never treat "refresh_content" as a signal to unpublish or delete a page
  • Never present Precision@10 = 0.300 to a client as a guarantee

Monitoring: re-run monthly on a fresh mid-panel month; re-audit if Precision@10 drops toward the base rate, if GSC coverage falls well below ~37%, or if the active client roster shifts significantly.
